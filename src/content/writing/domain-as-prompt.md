买下 jrxh.top 之后，我一直觉得它只被用成了一个网址。

直到某天把它拆开：

```text
jrxh  @  top  : ~ $
 │        │
 │        └─ 主机名，也是"做到顶端"的目标
 └─ 用户名
```

`jrxh@top:~$` 是一个合法、可读、完全属于这个域名的提示符。它比任何 Logo 都便宜，也比任何口号都具体。

## 先决定终端占多大

提示符很好用，但它有个陷阱：一旦做成全屏终端，主页就变成了一个需要学习的界面。

访客可能只想确认三件事：你是谁、你做过什么、怎么联系。这三件事不该藏在命令后面。

所以最后的结构是：

- 左边是正常的人类语言：标题、身份、两个按钮；
- 右边才是终端，默认输出 `whoami`、状态和目录；
- 终端可以玩，但不玩也能看完整个页面。

终端是记忆点，不是入口门槛。

## 命令就是导航

既然终端在页面上，就得让它真的有用，而不是装饰。

`whoami` 滚到关于，`ls projects` 滚到项目，`contact` 复制邮箱，`./spark.sh` 触发粒子并给一句灵感。`help` 列出全部命令。

每个命令都对应页面上一个真实存在的区块。终端不是另一个世界，它只是另一种到达方式。

## 彩蛋要有边界

404 页写成 `segmentation fault (core dumped)`，配一个"重新点火"按钮。

Konami code 会放一场两秒的粒子，仅此而已：没有声音、没有跳转、没有彩蛋收集系统。

彩蛋的价值在于"发现"，不在于"打扰"。触发一次就够了。

## 一致性比创意更难

提示符、橙色的 `top`、绿色的状态灯、`>_` 图标、终端里的三段启动输出，都来自同一个设定。

只要有一处漂移——比如某个页面突然用了圆角玻璃卡片——整个设定就散了。

> 域名给了一个提示符。剩下的工作，是让每个页面都配得上它。
